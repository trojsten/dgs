% The \makebox is exactly \linewidth wide whatever it holds. graphicx's scaling is not
% exact, so `width=\linewidth` can come out a hundredth of a point wider than the line,
% too little for an overfull warning but enough that the picture no longer fits beside
% `center`'s empty \item label: TeX breaks after the label, and an empty centred line --
% a whole \baselineskip -- opens above the drawing. `29/amusement-speed` lost 5 mm to it.
\NewDocumentCommand{\insertPicture}{O{} m}{%
    \begin{center}
        \makebox[\linewidth]{%
            \IfFileExists{\activeDirectory/#2}{%
                \includegraphics[#1]{\activeDirectory/#2}%
            }{%
                \includegraphics[#1]{example-image}%
            }%
        }%
    \end{center}
}

% An answer that is nothing but a picture. Two things went wrong here, and the eleven
% `answer.md` files that opened with an escaped non-breaking space and then a negative
% \vspace -- from -8mm to -13mm, one tuned number per drawing -- were papering over both.
%
% First, a run-in \subsection title needs a paragraph to sit in, and \insertPicture's
% `center` is vertical-mode material, so the title got deferred to the *next* paragraph and
% the problem number came out under its own picture. The non-breaking space was there to
% open a paragraph for the number to land in. \leavevmode does that without putting a
% character on the page.
%
% Second, `center` contributes \topsep above the drawing, which then floated a line and a
% half clear of the number. Here the picture instead stays in the number's own paragraph,
% raised so its top edge is level with the top of that line, and centred between two \hfill
% in whatever width the number leaves -- so it cannot collide with the number however wide
% it grows, and there is no length left to tune when a drawing is rescaled. A picture shorter
% than a line of text has no gap to close and is left on the baseline where it belongs.
%
% \parfillskip has to go to zero for the trailing \hfill to survive the line break, and is
% put back straight after, so an `answer-extra` following the picture still sets ragged.
% Local to a group: only the answer block turns this on, and a picture inside a problem or a
% solution keeps the breathing room \topsep is there for.
\newsavebox{\dgsPictureBox}
\NewDocumentCommand{\tightPictures}{}{%
    \RenewDocumentCommand{\insertPicture}{O{} m}{%
        \sbox\dgsPictureBox{%
            \IfFileExists{\activeDirectory/##2}{%
                \includegraphics[##1]{\activeDirectory/##2}%
            }{%
                \includegraphics[##1]{example-image}%
            }%
        }%
        \leavevmode
        \edef\dgsRestoreParfillskip{\parfillskip=\the\parfillskip\relax}%
        \parfillskip=0pt
        \hfill
        \ifdim\ht\dgsPictureBox>\ht\strutbox
            \raisebox{\dimexpr\ht\strutbox-\ht\dgsPictureBox\relax}{\usebox\dgsPictureBox}%
        \else
            \usebox\dgsPictureBox
        \fi
        \hfill\hbox{}%
        \par
        \dgsRestoreParfillskip
    }%
}

% A figure's height in the tear-off, where it differs from its height everywhere else.
%
% One `problem.tex` is built and every document inputs that same file, so a figure cannot be
% given two sizes by the renderer -- the booklet and the tear-off would be asking one fragment
% for both. The second size rides into the TeX as an ordinary `Gin` key instead, written by
% `core/filters/pictures.lua` because pandoc's writer drops any attribute it does not know.
%
% Ignored by default, so every document prints the plain `height` and a figure without the key
% is unaffected. The tear-off turns it on, inside the minipage that already groups each problem
% -- the same bargain as \tightPictures above, where the *including* context decides and the
% fragment it reads stays the same for everybody.
%
% The key is defined rather than merely tolerated: graphicx raises `Unknown key` on an option it
% has never heard of, so a no-op definition is what lets the other eight documents ignore it.
% \setkeys is right rather than \Gin@esetsize because `height` is already in the same option
% list, ahead of this one, and keyval honours the last assignment it is given.
%
% \tearoffPregap is the same bargain for the space *above* a figure. Vertical space is the
% binding constraint on a tear-off -- each problem has 94mm (phys) or 143mm (chem) and no more --
% and the gap `center` opens above a drawing is 7.3mm of it, of which 4.6mm is \topsep and
% \partopsep and 2.1mm is \parskip. Where a particular drawing needs some of that back, the
% figure says so once and the tear-off is the only document that acts on it: a negative \vspace
% tuned for a 94mm box would be wrong in a free-flowing booklet column, which is the defect the
% eleven hand-tuned negative \vspace in `answer.md` files were.
%
% No-op by default and redefined by \tearoffPictures, so it is one switch and not two -- and
% \RenewDocumentCommand is group-local, which is what the minipage around each problem relies on.
\makeatletter
\define@key{Gin}{tearoffheight}{}
\NewDocumentCommand{\tearoffPregap}{m}{}
\NewDocumentCommand{\tearoffPictures}{}{%
    \define@key{Gin}{tearoffheight}{\setkeys{Gin}{height=##1}}%
    \RenewDocumentCommand{\tearoffPregap}{m}{\vspace{##1}}%
    % A drawing is centred in whatever vertical space the text leaves it.
    %
    % The tear-off is the one document where that question has an answer: a problem sits in a box
    % of a fixed 94mm (phys) or 143mm (chem), so there *is* a leftover, and leaving all of it under
    % the drawing is a choice rather than the absence of one. Everywhere else the column is
    % free-flowing and there is no remaining space to centre anything in.
    %
    % \stretch, which is a second-order `fill`, and not \vfill, which is a first-order `fil`.
    % The minipage holding the problem is `[t][94mm][t]`, and that `t` puts a \vss at the foot of
    % the box -- a `fil`. Glue of the same order shares the slack, so three \vfill would each take
    % a third and the drawing would land a third of the way down instead of in the middle; a
    % `fill` outranks the \vss outright and leaves it nothing.
    %
    % The `center` stays. Its two \topsep are symmetric, so they do not shift the drawing, and
    % they keep it off the text in a box that is nearly full and has no slack to give.
    %
    % **2 above, 1 below, and 1 more at the foot of the problem**, which \tearoffTail lays down.
    % Equal glue above and below would be right only for a drawing that ends its problem, and
    % nine of volume 29's statements and a good many of chem's put a question after the figure;
    % with nothing to balance it the closing glue stretched and that question landed on the very
    % bottom edge of the box, a whole leftover away from the drawing it belongs to -- `chem/03`'s
    % reaction scheme is the worked example. Weighted 2:1:1 the leftover splits in half above the
    % drawing and a quarter each below it and at the foot, so a drawing that *does* end its
    % problem still sits at the middle of the white (half above, a quarter plus a quarter below),
    % and one that does not keeps its trailing line near it.
    \RenewDocumentCommand{\insertPicture}{O{} m}{%
        \par
        \vspace{\stretch{2}}%
        \begin{center}
            \makebox[\linewidth]{%
                \IfFileExists{\activeDirectory/##2}{%
                    \includegraphics[##1]{\activeDirectory/##2}%
                }{%
                    \includegraphics[##1]{example-image}%
                }%
            }%
        \end{center}
        \vspace{\stretch{1}}%
    }%
}

% The fourth share of a tear-off problem's leftover space, laid down after its last line.
%
% It is what keeps \insertPicture's 2:1:1 weighting honest: without a stretchable glue at the
% foot, the minipage's own \vss is the only thing left to take up the slack, and a \vss is a
% first-order `fil` against the drawing's second-order `fill`, so it would take none of it.
% A problem with no drawing has no competing glue and is unaffected -- this glue then takes
% the whole leftover, which is exactly what the \vss it stands in for was doing.
\NewDocumentCommand{\tearoffTail}{}{\par\vspace{\stretch{1}}}
\makeatother

% The join between the answer and an `answer-extra`, `answer-interval` or `answer-also`.
%
% Every part is a separate pandoc file and so ends in a newline, which TeX turns into a
% space; the negative thin space pulls that back, so the comma sits tight against the
% fragment before it. All of that is right only while the answer is running text. An answer
% that is a picture -- or a list, or a display, or anything else block-level -- has already
% ended its paragraph, so the comma opens a new one and prints on a line of its own with
% nothing before it. That is what `21/pv-to-vt-2` was doing: a diagram, then a paragraph
% opening ", Dbajte na to, ...".
%
% \ifvmode asks TeX which of the two actually happened instead of guessing from the source,
% so this is also right for an `answer.md` that is empty -- a problem whose whole answer
% lives in the extra, `28/john-doe` and `20/big-brother` -- and for whatever block-level
% answer is written next.
\NewDocumentCommand{\answerJoin}{}{%
    \ifvmode\noindent\else\!\textit{, }\fi
}

% The trailing block of a booklet -- the four author lists and the colophon under their rule.
% It is one credit, so it reads as one thing or not at all, and `21/sk` was splitting it
% four names from the end: the `Obrázky` heading dangling on the foot of page 48 with its one
% name overleaf, and the colophon stranded at the top of a mostly empty page 49.
%
% \vfill alone cannot prevent that. Glue is a legal breakpoint, so when the block does not
% fit TeX breaks inside it, and the \vfill that was meant to seat it at the foot of the page
% is discarded at the break -- which is why the remainder came out at the *top* of the next
% page rather than the bottom. The fill has to be \vspace*{\fill} for the same reason from
% the other side: plain glue is discarded at the head of a fresh page too, so after the
% \newpage below it would vanish and leave the block at the top again. The star is what makes
% it survive.
%
% So the block is collected into a box first, which cannot be broken at all, and only then is
% there anything to measure: if what is left of the page will not hold it, take a new page
% *before* laying down the \vfill, so the block is seated at the foot of whichever page it
% ends up on. \pagegoal is \maxdimen while a page is still empty, which is not a height and
% must not be compared against one.
%
% The \par\penalty is not decoration. \pagegoal and \pagetotal only describe the page as of
% the last time the page builder ran, and after an answer they can still be describing the
% page before: measured without it, `chem/03` read 744pt used of 692pt on a page holding one
% structural formula, and took a page it did not need. Contributing a penalty exercises the
% builder, and -100 doubles as a mildly attractive breakpoint, so if TeX does have to break
% it breaks here rather than somewhere worse. The idiom is `needspace`'s \Needspace*.
%
% It follows that a block taller than a whole page cannot be placed: it would overrun the
% bottom margin and say so, loudly, as an Overfull \vbox. At four author lists it is nowhere
% near, and splitting it would be the wrong answer anyway.
\newsavebox{\dgsFooterBox}
\NewDocumentEnvironment{footerBlock}{}{%
    \par
    \begin{lrbox}{\dgsFooterBox}%
    \begin{minipage}{\linewidth}%
}{%
    \end{minipage}%
    \end{lrbox}%
    \par\penalty-100
    \ifdim\pagegoal<\maxdimen
        \ifdim\dimexpr\pagegoal-\pagetotal\relax<\dimexpr\ht\dgsFooterBox+\dp\dgsFooterBox\relax
            \newpage
        \fi
    \fi
    \vspace*{\fill}%
    \usebox{\dgsFooterBox}%
}
