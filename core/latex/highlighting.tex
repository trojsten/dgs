% Pandoc's syntax highlighting macros, for fenced code blocks.
%
% A ```python block reaches the TeX as \begin{Shaded}\begin{Highlighting}[] with every token
% wrapped in a \XxxTok command. Pandoc supplies all of this through $highlighting-macros$ in
% its own LaTeX template -- but we emit fragments and bring our own preamble, so none of it
% was ever defined and every round holding a code block stopped at
%
%     ! LaTeX Error: Environment Shaded undefined.
%
% which is why FKS/35/2/1, 39/1/2, 40/1/3 and 40/2/1 have never produced a solutions PDF.
% Below is pandoc's own output for `pandoc --print-default-template=latex` filled in, taken
% verbatim so that an upgrade can be diffed against it: the token colours are its pygments
% default, and `Shaded` is its no-background form (the version that shades reaches for
% `framed`'s snugshade*, which would be a design decision rather than a fix).
%
% `fancyvrb` and `xcolor` are already required by the class; `fancyvrb`'s "currently unused"
% note there is now out of date.
%
% Verbatim does not break long lines -- it lets them run into the margin and says so as an
% Overfull \hbox. Ubuntu Mono at 12pt fits about 85 columns in the 180mm text block, and
% adding `,fontsize=\small` to the environment below buys roughly 17 more if a listing ever
% needs them.

\DefineVerbatimEnvironment{Highlighting}{Verbatim}{commandchars=\\\{\}}
\newenvironment{Shaded}{}{}
